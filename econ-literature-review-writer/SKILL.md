# Econ Literature Review Writer

## 使用边界

当用户已经给出文献、摘要、笔记、参考文献清单、BibTeX、EndNote 导出内容或若干论文 PDF/Markdown 提取文本，并希望生成或修改经济管理类文献综述时，使用本技能。

本技能只做报告写作、结构组织、逻辑综合和引用格式整理。它只处理用户已经给出的材料，不改变用户指定的文献集合，不按任何学校、机构或期刊库标准评价文献取舍。若发现作者、年份、题名、期刊、卷期页、DOI、研究方法等元数据缺失，只列入“需确认信息”，不自行补造。

## 输入路由规则

先根据用户一次提供的材料数量决定输出方式：

1. 用户只提供 1 篇文献、1 个 PDF、1 条完整参考文献或明确说“分析这篇文献”时，默认进入单篇文献分析模式。
2. 用户一次提供 2 篇及以上文献、多个 PDF、多个摘要、多个文献卡片或一个文献文件夹时，默认进入多篇文献综合综述模式。此时不要把多篇文献机械拆成若干篇单篇卡片，而应先做文献矩阵，再按主题、机制、方法或研究问题进行综合。
3. 用户提供多篇文献但明确要求“逐篇分析”“每篇都做卡片”“一篇一篇来”时，才逐篇输出单篇文献分析。
4. 用户已经有若干单篇文献卡片、读书笔记或抽取文本，并要求“整理综述”“放到一起”“综合一下”时，应把这些材料作为输入，生成多篇文献综合综述。

简化判断：一篇就精读，多篇就综合；除非用户明确要求逐篇。

## 工作原则

1. 综述不是文献罗列。需要把文献组织成研究问题、理论逻辑、方法演进、经验发现和争议焦点；如果只有一篇文献，则转为单篇精读，不强行写成综述；如果有多篇文献，则默认综合成主题化综述，不默认拆成逐篇卡片。
2. 优先尊重用户给定的文献集合。不要为了“显得更完整”凭空添加不存在或未核验的文献。
3. 对经济学、管理学、金融学、农业经济、数字经济、环境经济、政策评估等主题，应突出机制、识别策略、数据来源、异质性、政策含义和研究不足。
4. 中文综述避免空泛套话和机械排比，采用正式、清楚、可申报书或论文使用的表述。


## 单篇文献分析模式

当用户只提供 1 篇文献、1 篇论文全文、1 条完整参考文献或明确说“分析这篇文献”时，切换到单篇文献分析模式。此时不要强行生成完整文献综述，不要编造其他文献来形成主题群，也不要写国内外研究比较。若用户一次提供多篇文献，不应默认逐篇生成单篇分析，除非用户明确要求“逐篇”“每篇一张卡片”或“一篇一篇来”。

单篇文献分析的目标是把这篇文章读透，并转化为可复用的研究素材。推荐输出结构如下：

```markdown
# 单篇文献分析：[文献题名]

## 一、文献信息
- 作者：
- 年份：
- 题名：
- 期刊/来源：
- DOI/链接：
- 研究领域：

## 二、研究问题
说明文章要回答的核心问题，以及这个问题为什么重要。

## 三、理论基础与机制链条
提炼文章使用的理论视角、关键概念和机制关系。必要时用“原因 → 机制 → 结果”的方式重写。

## 四、数据、方法与识别思路
说明样本、变量、模型、识别策略、稳健性检验和异质性分析。若信息不足，标注“原文信息暂缺”。

## 五、主要结论
按逻辑顺序总结 3-5 条与用户研究最相关的发现。

## 六、创新与贡献
区分理论贡献、方法贡献、数据贡献和政策贡献。不要泛泛写“具有重要意义”。

## 七、局限与可借鉴之处
指出文章的局限，也说明它对用户选题、理论框架、变量设计、实证策略或政策建议有什么可借鉴之处。

## 八、可放入综述中的表述
给出 1-2 段可以直接嵌入文献综述的正式表述。段落应以“该文献如何支持某个研究脉络”为中心，而不是简单复述摘要。

## 九、参考文献格式
按 GB/T 7714-2015 整理；若元数据不足，列出需补全项。
```

单篇模式下仍要坚持两个边界：第一，只分析用户给出的这篇文献；第二，对原文没有的信息不补造。

## 多篇文献综合综述模式

当用户一次提供 2 篇及以上文献、多个 PDF、多个摘要、多个读书笔记或一个包含多篇文献的文件夹时，默认进入多篇文献综合综述模式。

多篇模式的目标不是把单篇分析简单排列，而是把文献放在同一个研究问题下重新组织。推荐流程如下：

1. 先建立文献矩阵，提取每篇文献的研究对象、核心问题、理论机制、数据方法、主要结论和可借鉴处。
2. 再做主题聚类，优先按研究问题、机制链条、方法路径、数据类型或政策含义组织，而不是按文献顺序堆叠。
3. 每个主题段落至少说明三件事：这一组文献共同讨论什么问题；不同文献之间是递进、互补、分歧还是方法差异；这些研究还留下什么不足。
4. 最后形成综合述评，明确现有研究已经解决了什么、尚未解决什么，以及用户研究可以从哪里切入。

多篇模式可使用以下结构：

```markdown
# 文献综述：[主题]

## 一、文献范围与综述问题
说明本次综述基于哪些用户提供的文献，以及要围绕什么研究问题进行综合。

## 二、文献矩阵
用表格列出作者年份、研究对象、核心问题、机制、方法、结论和可借鉴处。

## 三、主题化研究进展
### （一）主题一
### （二）主题二
### （三）主题三
围绕主题写综合段落，不按单篇文献流水账排列。

## 四、研究分歧与方法比较
比较不同文献在概念界定、变量口径、识别策略、样本范围和结论上的差异。

## 五、研究不足与未来方向
具体指出机制、数据、方法、情境、动态性或政策含义方面的不足。

## 六、可直接使用的综述段落
给出可放入论文、课题申报书或研究报告的正式段落。

## 七、参考文献
按用户提供文献整理，缺失元数据列入“需确认信息”。
```

多篇模式下仍要坚持两个边界：第一，只综合用户给出的文献和材料；第二，不为了形成“完整综述”而擅自添加未提供、未核验的文献。
## 输入整理

先把用户提供材料整理成一张文献矩阵。字段可包括：

| 字段 | 说明 |
|---|---|
| 编号 | C1、C2 或 E1、E2，也可按用户原编号 |
| 作者年份 | 如“张三等，2024”或“Smith et al., 2023” |
| 研究对象 | 企业、农户、家庭、地区、行业、国家等 |
| 核心问题 | 文献要解释的因果关系或理论问题 |
| 理论机制 | 中介机制、传导路径、约束条件 |
| 数据与方法 | DID、RD、IV、PSM、结构模型、案例研究等 |
| 主要结论 | 与用户主题最相关的结论 |
| 局限或可借鉴处 | 可用于述评和研究不足的内容 |
| 可放入章节 | 归入哪一主题段落 |

若材料缺失，不要编造。用“信息暂缺”标注，或在正文中弱化处理。

## 推荐流程

### Step 1: 明确综述目的

先判断综述服务于哪类文本：课题申报、论文引言、研究综述章节、开题报告、政策报告或课程讲稿。不同场景的重点不同：

- 课题申报：强调研究现状、趋势、不足和本课题切入点。
- 论文引言：强调问题提出、文献缺口和边际贡献。
- 综述章节：强调分类体系、文献谱系和批判性评述。
- 政策报告：强调现实问题、证据共识和政策启示。

### Step 2: 主题聚类

不要按“国内/国外”机械平铺。优先按研究问题或机制聚类，例如：

- 概念界定与理论基础
- 政策背景与制度演进
- 影响效应评估
- 作用机制识别
- 异质性与边界条件
- 分配效应与福利后果
- 风险、约束与治理问题
- 方法与数据进展

如果用户明确要求国内外研究现状，可采用“国内研究现状、国外研究现状、述评”结构，但每部分内部仍需按主题组织。

### Step 3: 写综合段落

每个段落应包含四类信息：

1. 该主题的核心问题是什么；
2. 代表性研究从哪些角度回答；
3. 这些研究之间是递进、对比、补充还是分歧；
4. 仍有什么不足，如何引出用户的研究。

避免这种写法：

> A 研究了甲，B 研究了乙，C 研究了丙。

优先写成：

> 围绕甲问题，既有研究大体形成了两条解释路径：一类从制度激励出发，强调政策约束对主体行为的塑造；另一类从资源配置效率出发，关注市场接入、要素流动和组织能力的变化。前者有助于解释政策效应的方向，后者则进一步揭示效应为何在不同地区和主体之间分化。由此看，现有研究已经证明甲的重要性，但对乙环节的识别仍不充分。

### Step 4: 研究述评

述评要具体，不要只写“研究不足、方法单一、数据不够”。可以从以下角度提出：

- 机制断点：已有研究验证总效应较多，但对需求转化、产业承接、收益分配、风险缓冲等环节识别不足。
- 跨层异质性：县域条件、企业能力、农户禀赋或行业属性没有同时纳入。
- 动态持续性：短期效应多，长期稳定性、韧性和路径依赖讨论不足。
- 指标口径：现有指标偏向规模或均值，较少反映稳定性、质量和分配。
- 因果识别：政策叠加、空间溢出、选择偏误或反向因果处理不足。
- 理论整合：经验发现较多，但缺少统一传导框架。

### Step 5: 输出结构

默认输出 Markdown。常用结构：

```markdown
# 文献综述：[主题]

## 一、研究背景与问题提出
## 二、概念界定与理论基础
## 三、国内外研究进展
### （一）主题一
### （二）主题二
### （三）主题三
## 四、研究述评
## 五、未来研究方向或本研究切入点
## 参考文献
```

对于课题申报书，可压缩为：

```markdown
## 国内外研究现状和发展趋势
## 现有研究不足
## 本课题的研究空间
```

## 引用与参考文献

如需整理参考文献，使用 `references/gb-t-7714-2015.md`。如果用户提供 DOI、卷期页、作者、年份等信息不完整，不要补造；可以保留缺失项，或列入“需补全元数据”。

可使用 `scripts/citation_formatter.py` 对结构化文献字典做 GB/T 7714-2015 初步格式化，但最终仍需人工核对。

## 交付检查清单

交付前检查：

- 是否围绕用户研究问题组织，而不是围绕文献顺序组织；
- 多篇文献任务是否至少形成 2-4 个清晰主题群；单篇文献任务是否切换为精读分析；
- 是否有研究之间的递进、分歧或互补关系；
- 是否明确写出文献不足，并能自然引出用户研究；
- 是否没有编造文献、DOI、期刊信息和数据结论；
- 是否没有改变用户指定的文献集合；
- 是否只基于用户提供材料进行综合分析。
